# 导出、查询和事务

## 导出

导出地址为：`/api/export/students`、`dormitories`、`buildings`、`all`，均仅管理员可访问。

- 楼栋统计在一次分组聚合查询中完成，不随楼栋数量增加数据库往返次数。单独导出与全量导出共用相同工作表生成逻辑。
- 学生表包含学籍、院系与辅导员信息；宿舍表分别列出入住状态和房间可用状态。
- `all` 生成 25 张工作表，包括导出说明、学生与宿舍楼栋、床位、住宿申请与历史、宿舍长、报修与处理记录、公告与回执、消息、留宿外宿、访客、检查、账单与收退款、资产与交接、账号状态、楼栋权限、规则、批次摘要和审计。
- 密码、导入预览内容、凭据版本和附件文件不包含在 Excel 中。附件只保留业务记录中的引用；数据库恢复仍使用[完整备份恢复脚本](BACKUP-RESTORE.md)。
- MySQL 在同一 `REPEATABLE READ` 只读事务内读取所有工作表；SQLite 使用同一 `SERIALIZABLE` 事务。构建完临时工作表后释放数据库连接，再向客户端输出。
- JDBC 逐行读取，SXSSF 仅保留 100 行窗口，列宽固定，超过单表行数限制时拆分工作表。取消下载或输出异常会关闭工作簿、清理临时文件并归还并发名额。
- 默认每个后端实例最多并行导出 2 份，超过时返回 HTTP 429；可设置 `app.export.max-concurrent`。临时目录需保留足够磁盘空间。导出仍会扫描所选业务数据，因此大量导出应避开高峰。

## 事务与锁

MySQL 普通写入使用 `READ COMMITTED`，等待锁后读取最新已提交数据。导出单独使用快照隔离，不受此默认设置影响。SQLite 保持单写者与 `SERIALIZABLE`。

`DomainLocks` 在实际数据库事务中按以下顺序获取锁，事务提交或回滚时由数据库释放：

1. 楼栋结构保护：普通业务共享同一保护行；楼栋改名、增删改房等结构修改独占它。SQLite 提前执行写操作取得数据库写锁，避免先读后写升级冲突。
2. 按编号升序锁定涉及的学生。
3. 按编号升序锁定当前房间和目标房间。
4. 锁定账单、资产、维修工单或审批等具体业务记录。

普通操作不会更新全部楼栋与宿舍。不同学生、不同房间的操作可在 MySQL 上并行。账单和物品交接也锁定涉及的学生，以便与退宿结算检查保持一致；同一学生的多个财务操作仍会互相等待。

管理端入住、调宿、床位预留、住宿审批、批量分配、费用、资产和维修相关入口复用上述顺序。批量操作先锁定全批涉及的学生和房间，再执行各项修改。生成宿舍账单及宿舍长任命时，如等待锁期间名单发生变化，返回 409，要求刷新后重新操作。

结构修改仍会短暂阻塞普通写入；SQLite 的数据库级单写者限制没有改变。不要绕过业务服务直接修改住宿记录，也不要在其他实例部署仍使用旧公共锁规则的版本。

## 查询与选择框

业务列表支持精确 `state`、`building` 和日期区间 `from/to`，参数按业务类型验证。日期为 `YYYY-MM-DD`，开始与结束日均包含。历史按入住日期、宿舍长按任命日期、访客按到访日期、交接按领用日期、学生档案按归档日期，其余有时间字段的业务按创建日期筛选。

表单和批量分配使用 `/api/business/options/{source}`，默认每页 50、最多 100 项，支持姓名／编号前缀搜索及按已选 `ids` 回查。权限过滤在查询内完成，不能利用编号回查获取管理范围外的数据。未入住学生选项使用 `unhoused=true`，同时限定在校。

选择框保留跨页选择，忽略过期搜索响应，并回查第一页之外的默认选中项。每个弹窗使用独立选择框状态，关闭后销毁；成功提交后重建需要刷新的选项。`/options?include=...` 与数组列表接口仅用于兼容，当前页面使用分页接口。

## 启动与核对

`business_migration` 记录已完成升级：版本 1 为原系统床位／住宿历史接入，版本 2 为查询索引补建。接入成功后重复启动不再逐房核对或重写人数；索引升级失败不写入完成标记，下次重试时通过元数据跳过已经建好的索引。

管理员可在“住宿数据核对”查看按页返回的异常报告（`/api/business/lists/consistency`）。报告检查登记人数、实际入住、床位数量与归属、未结束的入住历史、宿舍长人数及失效的宿舍引用。报告只读取数据，处理异常前应先核实记录和备份。

## 测试

后端集成测试使用临时 SQLite 文件或单独的 `susheguanli_test_*` MySQL 库，覆盖并发入住、反向调宿、退宿与账单竞争、预留冲突、无关房间并行、导出期间住宿变化、导出断连／限流、分组统计、批量导出、权限与筛选、启动迁移和异常报告。

浏览器交互检查使用真实 Vue 页面与模拟 API，验证筛选、选项分页、跨页多选、默认值回查、表单载荷和过期响应处理：

```powershell
npm run dev --prefix frontend -- --port 5176 --strictPort
node frontend/tests/optimization-ui.cjs
```

需要另外安装 Playwright 和 Chrome。脚本默认从 `artifacts/browser/node_modules/playwright` 加载，也可通过 `PLAYWRIGHT_MODULE`、`CHROME_PATH`、`UI_TEST_URL` 指定模块路径、浏览器路径和页面地址。

这些是功能和并发测试。实际数据量下的导出耗时、吞吐量和内存占用需要另做压测。

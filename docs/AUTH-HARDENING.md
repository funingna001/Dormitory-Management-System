# 认证流程优化

## 学籍与账号

学生账号统一由管理员核验后通过建档、账号补建或名单导入开通。前端移除自助注册入口、字段和分支。原注册 API 统一返回 403，不解析注册字段、不校验验证码、不查询学号是否存在。已有用户、密码和业务档案没有批量改写。

新建档案和导入预览遇到已有但未绑定档案的账号时返回冲突，要求管理员先核验身份；不自动继承其密码，也不自动删除或覆盖该账号。旧账号核验及处理需由管理员单独办理。

## 密码和版本

认证查询同时读取用户、密码哈希、启用状态、凭据版本与强制改密标志。验证密码后再次复核哈希、版本及角色，建立会话时始终保存被验证的版本；后续改密或停用会使版本校验失败。

改密和管理员重置先锁定对应用户行。改密事务返回自己产生的凭据版本，当前会话不再在事务结束后取可能属于另一笔重置的最新版本。

## 限流与验证码

采用独立、有容量上限和到期淘汰的内存窗口：登录来源每分钟 60 次、验证码每分钟 60 次、通过验证码后的来源与账号组合每 15 分钟 10 次。成功登录清除对应密码窗口。错误验证码不累计账号密码额度；用户名去除首尾空白并转小写后用于计数。

容量满时淘汰最早窗口，不因计数表满而拒绝所有新用户；清理按到期顺序进行，不逐次扫描整个计数表。窗口是单实例状态；多实例部署需另行使用共享计数后端，并考虑校园出口地址共享情况。

验证码写入和一次性读取删除在同会话临界区内执行，使用现有两分钟有效期。请求字段限制为四位数字。当前实现适用于本项目单实例内存 Session 部署。

## 会话恢复、代理与数据库故障

前端收到 401 会清除认证状态和缓存 CSRF；提交登录前主动获取当前 Session 的 CSRF。写操作先收到 403 时，通过只读 `/auth/me` 确认会话是否过期，再引导重新登录。登录成功后获取新令牌并同步 `/auth/me`；若网络暂时故障，保留待同步状态、清空密码，并通过“重新同步登录状态”按钮继续，不重放登录 POST。没有增加其他写操作的自动重试。

已认证会话必须携带非负 `Long` 类型凭据版本。缺失、字符串、浮点数和负数都返回 401 并清理会话；这类请求在查询数据库前拒绝。测试用模拟身份由测试配置补上版本，生产过滤器没有兼容放行分支。

Nginx 覆盖客户端传入的 `X-Forwarded-For` 和 `X-Forwarded-Proto`。后端使用 Tomcat 原生代理解析，默认只信任回环代理。代理部署在其他地址时显式设置 `TRUSTED_PROXY_PATTERN`，只列入受控代理；后端端口仍应限制公开访问。

查询账号只有“没有记录”返回空值，数据库异常不再被当作密码错误或账号不存在。会话过滤器遇到数据库异常返回 503，保留已有 Session；控制器中的数据库故障也返回服务异常。

会话过滤器使用一次 JOIN 读取认证状态，并附在当前请求供 `/auth/me` 复用，常规身份检查由 4 次查询减少为 1 次，`/auth/me` 由 6 次减少为 1 次。没有增加跨请求身份缓存，保留即时停用和凭据撤销检查。

## 验证

新增测试覆盖旧密码与新版本错配、数据库故障保留会话、单次状态查询、验证码并发消费、限流容量隔离、可信代理与伪造头、错误验证码误锁、学号抢注和旧账号绑定冲突。浏览器恢复检查使用真实 Vue 页面与模拟 API：`node frontend/tests/auth-recovery.cjs`（Vite 端口 5176，Playwright 路径同其他浏览器测试）。

## 可配置限流和等待时间

环境变量（也可使用对应的 `app.auth.limits.*` Spring 配置）：

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `AUTH_LOGIN_IP_LIMIT` | 60 | 同来源登录窗口内请求数 |
| `AUTH_CAPTCHA_LIMIT` | 60 | 同来源验证码窗口内请求数 |
| `AUTH_PASSWORD_LIMIT` | 10 | 验证码通过后，来源与账号组合的请求数 |
| `AUTH_LOGIN_WINDOW_SECONDS` | 60 | 登录来源窗口秒数 |
| `AUTH_CAPTCHA_WINDOW_SECONDS` | 60 | 验证码窗口秒数 |
| `AUTH_PASSWORD_WINDOW_SECONDS` | 900 | 密码窗口秒数 |
| `AUTH_LIMIT_CAPACITY` | 10000 | 每类窗口最多保存的计数项 |

次数和容量须为 1–100000，窗口为 1–86400 秒，非法配置会阻止启动。429 携带当前窗口剩余秒数 `Retry-After`；跨域响应允许前端读取该头。校园共享出口应同时评估登录与验证码额度，调整后重启生效，不直接套用其他网络的阈值。

入口突发回归使用独立测试环境：200 次同地址、8 并发、验证码错误的请求，默认放行 60 次进入验证码校验（400），其余 140 次返回 429 且包含 `Retry-After`。它验证入口限流与并发计数，不包含真实密码哈希成本，不能作为生产吞吐量结论。

## 认证审计与指标

管理员可 GET `/api/auth/metrics` 读取本实例聚合计数及近期事件，匿名返回 401，其他角色返回 403。覆盖登录成功、密码拒绝、验证码拒绝、限流、会话撤销原因、数据库故障、退出和停用注册入口调用。

近期事件是有界内存环，默认 `AUTH_AUDIT_CAPACITY=500`（1–10000），满后删除最旧事件。用户名只保存 SHA-256 截断关联标签，源地址最长 64 字符，不保存密码、验证码、Cookie、Session ID 或请求正文。标签用于关联事件，不是身份验证凭据。

默认每 `AUTH_AUDIT_SUMMARY_MS=60000` 毫秒仅在计数变化时输出一次聚合日志，不同步写数据库，不为大量失败请求创建无限队列。近期事件和计数在实例重启后清空；需长期保留事件时应接入独立、受控的日志存储。本次未安装外部监控或日志服务。

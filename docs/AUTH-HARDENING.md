# 认证与会话

## 账号开通

学生账号由管理员通过建档、补建或名单导入开通。公开注册接口返回 403，不查询学号是否存在。建档或导入遇到已有但未绑定档案的账号时返回冲突，需要管理员先核验。

## 密码和凭据版本

认证查询读取用户、密码哈希、启用状态、凭据版本和强制改密标志。验证密码后再次复核哈希、版本及角色，会话保存本次验证的版本；后续改密、重置或停用账号会使旧版本失效。

改密和管理员重置都会先锁定用户行。改密事务返回自己产生的版本，当前会话使用该版本，避免并发重置时误用另一笔事务的结果。

## 验证码与限流

验证码为四位数字，有效期两分钟，校验后立即作废。同一会话内的写入和消费使用同步控制，避免并发重复校验。

登录来源、验证码刷新、来源与账号组合分别计数。错误验证码不计入账号密码额度；登录成功后清除对应密码窗口。计数前会去除用户名首尾空白并转为小写。

限流使用有容量上限的内存窗口，按到期时间清理，容量满时淘汰最早窗口。计数是单实例状态，多实例部署需要共享计数后端；校园网多人共用出口时，也需要调整来源额度。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `AUTH_LOGIN_IP_LIMIT` | 60 | 同来源登录窗口内请求数 |
| `AUTH_CAPTCHA_LIMIT` | 60 | 同来源验证码窗口内请求数 |
| `AUTH_PASSWORD_LIMIT` | 10 | 验证码通过后，来源与账号组合的请求数 |
| `AUTH_LOGIN_WINDOW_SECONDS` | 60 | 登录来源窗口秒数 |
| `AUTH_CAPTCHA_WINDOW_SECONDS` | 60 | 验证码窗口秒数 |
| `AUTH_PASSWORD_WINDOW_SECONDS` | 900 | 密码窗口秒数 |
| `AUTH_LIMIT_CAPACITY` | 10000 | 每类窗口最多保存的计数项 |

次数和容量范围为 1–100000，窗口范围为 1–86400 秒，非法配置会阻止启动。超额请求返回 429，`Retry-After` 给出当前窗口剩余秒数；修改配置后需重启。

## 会话恢复

前端收到 401 时清除登录状态和缓存的 CSRF token。写请求收到 403 时，先通过只读 `/api/auth/me` 判断会话是否过期，不直接重试原操作。

登录前获取当前会话的 CSRF token；登录成功后获取新 token，再同步用户信息。如果同步阶段断网，页面清空密码并保留待同步状态，用户可点击“重新同步登录状态”继续，不会重复提交登录请求。

服务端会话必须携带非负 `Long` 类型的凭据版本，缺失或类型错误时返回 401 并清理会话。每次请求通过一次 JOIN 查询认证状态，结果供 `/api/auth/me` 复用，不做跨请求身份缓存。

数据库查询异常返回 503，已有 Session 保留；查不到账号才按身份失效处理。

## 反向代理

Nginx 覆盖客户端传入的 `X-Forwarded-For` 和 `X-Forwarded-Proto`。后端使用 Tomcat 原生代理解析，默认只信任回环地址。

代理位于其他地址时，用 `TRUSTED_PROXY_PATTERN` 指定受控代理，同时限制后端端口的访问范围。配置示例见 [nginx.conf](../deploy/nginx.conf)。

## 认证记录

管理员可通过 `GET /api/auth/metrics` 查看本实例聚合计数和近期事件。事件包括登录、密码或验证码拒绝、限流、会话撤销、数据库故障、退出，以及调用已关闭注册入口。

近期事件使用内存环，默认保留 500 条，由 `AUTH_AUDIT_CAPACITY` 设置，范围为 1–10000。用户名使用 SHA-256 截断标签关联，源地址最多 64 字符，不记录密码、验证码、Cookie、Session ID 或请求正文。

`AUTH_AUDIT_SUMMARY_MS` 默认 60000 毫秒，计数变化时才输出聚合日志。计数和近期事件重启后清空；需要长期保留时，应另接受控日志存储。

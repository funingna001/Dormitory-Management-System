# 业务说明

日常操作从管理员功能首页进入。宿管、辅导员、学生和维修人员登录后，只能看到各自有权限的页面。

## 宿舍与住宿

| 功能 | 规则 |
| --- | --- |
| 床位 | 按房间容量生成编号床位，状态有空闲、已入住、预留和停用。预留可指定学生及到期时间 |
| 房间状态 | 正常、维修中、已关闭。维修或关闭的房间可以保留现有住户、办理移出，不能安排新入住 |
| 入住、调宿、退宿 | 学生提交申请，管理员、负责宿管或辅导员审核，管理员或负责宿管办理。调宿在同一事务中释放原床位、占用目标床位 |
| 住宿历史 | 保存入住与退宿时间、原因和经办人。学生归档后仍保留住宿记录及费用流水 |
| 宿舍长 | 管理员或本楼宿管从已入住成员中任命，记录任命、离任和交接原因，不按学号自动选择 |

审批通过后还要点击“办理完成”，才会更新实际住宿关系。申请预留默认三天，也可指定未来 30 天内的截止时间；查询或分配前会检查并释放过期预留。

## 学生与账号

学生档案包含学号、班级、年级、学院、专业和负责辅导员。毕业、休学或退学时办理归档，并停用账号。

学生账号由管理员建档、补建或导入开通，工作人员账号在“账号与楼栋权限”创建。宿管需要分配负责楼栋，辅导员与学生的对应关系在档案中设置。新账号首次登录需要修改初始密码。

用户可自行改密，管理员可重置密码或停用账号；改密、重置和停用会使其他旧会话失效。具体权限见 [页面与数据权限](ROLE-PERMISSIONS.md)。

## 校园服务

| 功能 | 操作流程 |
| --- | --- |
| 报修 | 学生提交 → 管理员或宿管派单 → 维修人员处理 → 学生验收。支持改派、优先级调整、退回重修和评价，详见 [报修流程](REPAIR-WORKFLOW.md) |
| 通知 | 发布全校或指定楼栋公告，记录已读状态；住宿审批、维修、费用等操作会产生个人站内消息 |
| 留宿、外宿、晚归 | 学生填写起止时间、原因和联系方式，经审核后登记实际结束或返校时间；同类申请不能重复重叠 |
| 访客 | 宿管登记被访学生、访客信息、到访和预计离开时间，离开时补记实际时间；学生只能查看自己的访客记录 |
| 卫生与安全检查 | 记录类型、评分、问题、照片和整改期限；住户提交整改说明或照片，宿管复查通过或退回 |

同寝室成员可查看公共报修，由报修人或当前宿舍长验收。维修人员只能处理已派给自己的工单。

## 费用与物品

费用按学生出账，也可按宿舍当前住户分摊。金额以整数分存储，分摊时处理尾差。管理员登记已核实的缴费或退款，凭据号不能重复，不能超收或超退。学生只能查本人账单和流水。

家具、设备和钥匙各有独立编号，记录所属房间、领用人，以及归还、损坏、丢失、维修和报废情况。领用人必须住在该宿舍。

费用是台账，收退款需要人工核实。通知使用站内消息，访客和晚归使用人工登记；项目未接入第三方支付、短信、门禁或外部财务系统。

## 批量导入与分配

管理员下载 XLSX 模板并填写学生资料，上传后先校验和预览，再整批确认。预览 15 分钟内有效，只能确认一次；初始密码只保存哈希，不出现在预览结果中。

批量分配按性别、目标楼栋和可用床位筛选，优先将同学院、同年级、同班级学生安排在一起。确认时重新检查学生及床位状态，任一记录冲突时整批回滚。

## 住宿业务规则

在“住宿业务规则”中设置以下选项，默认均开启：

- 退宿或跨宿舍调整前结清费用。
- 退宿或跨宿舍调整前完成物品交接。
- 允许所有已入住学生报修；关闭后仅宿舍长可提交。

各校的审批链、收费标准和门禁时间需要按实际情况另行配置或开发。

## 旧数据接入

业务表与原有的学生、宿舍、楼栋、用户及报修表分别保存。升级前先按 [备份说明](BACKUP-RESTORE.md)保存数据库和附件。

首次接入时，系统为已有房间补建床位，根据当前住户建立住宿记录，并保留原宿舍长。这类记录注明“原系统记录接入”，接入时间不代表实际入住日期。迁移版本保存在 `business_migration`，重复启动不会重复生成床位或住宿历史。

管理员可在“住宿数据核对”检查人数、床位和历史记录的异常。页面只列出问题，处理前需要核实原始记录。

接口字段见 [业务 API](BUSINESS-API.md)，事务和锁的实现见 [导出、查询和事务](OPTIMIZATIONS.md)。
